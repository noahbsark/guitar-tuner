# Guitar Studio pre-release verification

This branch is a private-development candidate, not a release. Production deployment, sitemap/indexing/SEO, and new monetization work are excluded.

## Implemented scope

- Browser DSP amplifier, pedals, microphone and file playback, demo, waveform, practice tools and exports.
- Optional dual audio and camera takes; local opt-in IndexedDB library (10 saved takes / 150 MB, five unsaved takes); rename, delete, preview and reamp.
- Non-destructive audio trim, fades and peak normalization to WAV; video trim and audio fades via local browser re-encoding where supported.
- Four attributed MIT NAM starter models (two actual RiffSmith full-rig captures, two ToneTinkerer virtual circuit models); custom model loading, stopped-transport switching, conventional fallback.
- Mic-to-pickup-like EQ, body resonance, quiet-room gate calibration, headphone-only monitoring, conservative emergency stop and narrow-band cutoff, separate offline reference-cancellation experiment.
- Responsive controls, reduced motion, viewport tests and expanded browser CI.

## Evidence and limitations

- Latest source syntax checks and all 23 mock regression checks passed. The deterministic synthetic echo fixture recovered 20 ms delay and about 39 dB reduction with synthetic additive noise. This does not establish real-room echo removal, musical preservation or safe live speaker monitoring.
- Browser run 46039634476 completed 56 passes, two failures and five skips. Normal Firefox recording, neural processing, camera and storage tests passed after installing the virtual audio dependencies. The two WebKit failures were a Blob storage fixture and late-permission injection. Follow-up code uses ArrayBuffer storage for new recordings with legacy Blob reads, and a deterministic after-load permission mock. Verify follow-up CI; the fixes are not yet certified. No hardware QA is implied by browser tests.
- Library, video, editor, capture and responsive tests ran; both failures described above remain to be rechecked. Some WebKit capture tests were skipped because capabilities were unavailable. Inspect screenshots and accessibility reports. Browser storage can be evicted; users should download important files.
- NAM runtime is generated by the pinned preparation script. A preview that does not stage it will retain only the conventional amp. Verify complete compiled dependency notices and distribution rights before public hosting. No third-party commercial capture catalog is integrated.
- Neural offline WAV export and reference EQ remain disabled in neural mode; real-time export is available where MediaRecorder is supported. Arbitrary model sample-rate conversion is not implemented. Actual magnetic-pickup reconstruction would require appropriately licensed paired and aligned mic/pickup recordings and listening evaluation.
- Video editing depends on local decoding, seeking, captureStream and MediaRecorder; some recorder containers lack seekable duration metadata. Actual A/V sync and device limits need real-device evaluation.

## Manual release-blocking QA (do not release until reviewed)

1. Test Chrome, Firefox, Safari on actual desktop and Android/iPhone devices, with real microphones, direct input, camera, headphones. Verify permission rejection, pending-prompt cancellation, tab backgrounding, track release, emergency stop, and safe low-volume startup. Do not enable live speaker monitoring.
2. Compare same performance recorded through a microphone and direct pickup; compare conventional and neural presets, clipping, dynamics, noise gate, sound quality, latency and CPU/battery at 48 kHz. Listen to resulting audio, not just signal-level tests. Keep a measured QA log.
3. Test dual audio/video recordings, A/V alignment with visible/audible pluck, download playback, trim/fade duration, cancellation, library reload/rename/delete, quotas and unsupported browser recovery. Verify originals remain unchanged.
4. Verify mobile touch targets, layout, keyboard accessibility, screen-reader labels, contrast, orientation, and screenshots. Resolve failing applicable CI tests and record skipped capability coverage.
5. Review all generated runtime and model license notices, local privacy behavior, storage limitations and performance. Do not claim exact artist/equipment equivalence.
6. Obtain owner approval before any production merge or deployment. Keep noindex, existing production settings, tuner, content publishing, SEO and monetization unchanged until separately authorized.
